# feature-node-graph

ノードグラフで手順を組み、画像認識でゲームを自動操作するツールです。

- `editor/` … ノードグラフの画面（単一HTML。ブラウザで直接開ける）
- `runner/` … 自動操作のエンジン（画像認識・クリック・中断・画面表示）
- `games/<ゲーム名>/` … ゲームごとの固有部分（参照画像、ウィンドウの扱い、手順）

現在は `games/nikke/` の「迎撃戦」だけが入っています。

## 構成

```
editor/
  feature-node-graph.html          ノードグラフ画面（本体）
  feature-node-graph.backup.html   最初の状態のバックアップ。触らない（それ以外の過去の状態はgitの履歴で戻せる）
runner/
  flow.py              手順JSONを読んで順番に実行する
  wait_for_image.py    画像を探してクリック。リトライ・押し直し・中断判定
  highlight.py         クリック対象を白縁取りの赤枠で表示
  overlay.py           実行中に画面を薄暗くして「自動操作中」と表示
  listen_for_key.py    キー入力の監視（何か押されたら中断）
  singleton_flag.py    中断フラグをファイル間で共有するシングルトン
  debug_match.py       画像の一致率を調べる道具
games/nikke/
  img/                 クリックする画像（画面認識に使う）
  screens/             各ステップの画面全体（editorでの表示用。認識には使わない）
  window.py            NIKKEのウィンドウを前面にする
  flows/               手順JSON（editorで組んで書き出したもの）
    interception.json       迎撃戦（本番）
    interception_test.json  迎撃戦-特殊個体まで進んでホームに戻る（動作確認用。戦闘は始めない）
server.py              ブラウザとの橋渡し（画面から開始/停止できる）
script.py              画面なしで実行するエントリーポイント
引き継ぎ_機能ノードグラフ.txt   editor の作業引き継ぎ書（作業ルールもここ）
```

## 必要なもの

- Python 3.13
- ゲームのPC版クライアント

```bash
pip install -r requirements.txt
```

`opencv-python` は必須です。入っていないと一致率（confidence）による判定ができず、
「画像が見つかりません」という紛らわしいエラーになります。

## 実行方法

**管理者権限で実行する必要があります。**

NIKKEは管理者権限で動作しているため、通常の権限で起動したプログラムからは
Windowsの保護機能（UIPI）によってマウス操作がブロックされ、カーソルすら動きません。
VSCodeやターミナルを「管理者として実行」で起動してください。

### 画面から実行する（推奨）

リポジトリのルートフォルダで `server.py` を起動すると、ブラウザが自動で開きます。

```bash
python server.py
```

- ブラウザの画面右上に **「▶ 開始」「■ 停止」** が出ます（`server.py` 経由で開いた時だけ。
  HTMLをファイルとして直接開いた時はメモ用途のまま何も変わりません）
- 初回は画面に手順が無いので、「データ」→「ファイルを選ぶ」で `games/nikke/flows/interception.json` を読み込みます。
  一度読み込めば、次回からはブラウザが覚えています
- ゲームをロビー画面にして「開始」を押すと、**今画面に出ている手順**が実行されます。
  ノードを消したり一致率を変えたりした状態で押せば、その通りに動きます
- 実行中は処理中のノードが黄色、終わったノードは緑（一致率付き）、失敗は赤、中断は灰色になります
- 「停止」を押すか、何かキーを押すと中断します。`server.py` の終了は Ctrl+C
- ノードには画像が出ます。上がそのステップの画面全体（項目「画面」）、下がクリックする画像（項目「画像」）です
- ノードを選ぶと右パネルに **「この画面を撮る」** が出ます。ゲームを撮りたい画面にしてから押すと、
  ゲームの窓だけを撮って `games/nikke/screens/<ノード名>_<日時>.png` に保存し、項目「画面」に自動で入ります。
  撮るたびに新しいファイルになるので、前の画像も残って見比べられます（不要な分は手で消してください）
- 別のポートで起動したい時は `python server.py --port 8766`

### 画面なしで実行する

```bash
python script.py                                # 迎撃戦（既定）
python script.py games/nikke/flows/xxx.json     # 別の手順
```

どちらの場合も、実行中は画面が薄暗くなり「自動操作中」と表示されます。

## 手順を組む（editor）

手順は `editor/feature-node-graph.html` をブラウザで開いてノードとして組み、JSONに書き出して
`games/nikke/flows/` に置きます。逆に、既存のJSONを「データ」→「読み込む」で開いて編集もできます。

ノードと手順の対応は次の通りです。**項目名は決め打ち**です。

| ノードの要素 | 意味 | 省略時 |
|---|---|---|
| ノード名 | ステップ名（ログに出る） | — |
| 項目「画像」 | クリックする画像のファイル名（`games/nikke/img/` 内） | 必須 |
| 項目「一致率」 | 画像認識の閾値 0〜1 | 0.7 |
| 項目「リトライ」 | 画像が出るまで待つ回数（1回1秒） | 10 |
| 項目「画面」 | そのステップの画面全体のファイル名（`games/nikke/screens/` 内）。表示専用で、無くても動く | — |

順番は線で決まります。線が入ってこないノードが開始点で、`from → to` の向きに進みます。
今は**1本道だけ**対応しています。分岐、つながっていないノード、輪、項目の抜けなどは
実行前にチェックされ、どのノードが原因かを添えて止まります。

```
手順ファイルに問題があります: ノード「迎撃戦」から線が2本以上出ています。分岐にはまだ対応していません
```

## 今後の予定

1. ~~手順をJSONから読む~~ … 完了
2. ~~開始/停止ボタンと進行表示~~ … 完了
3. ~~ノードに画像を表示~~ … 完了（項目「画面」「画像」を裏方サーバーが配って表示）
4. ~~右パネルに「この画面を撮る」ボタン~~ … 完了
5. 画面全体から範囲をなぞってクリック画像を切り出す
6. グループ（手順のまとまり）を複数指定して順に実行

## クリックが効かない時

クリック後、1.5秒待っても同じ画像が残っていれば「画面が変わっていない」と判断して押し直します（最大3回）。

```
クリックしましたが画面が変わっていません（アークがまだ見えている。一致率0.983）。1/3回目、押し直します
```

これが頻発する場合、次を疑ってください。

- **ゲーム以外の窓が前面になっている** … `games/nikke/window.py` はタイトルが `NIKKE` と完全一致し、
  かつ `nikke.exe` の窓だけを対象にしています（VSCodeやブラウザのタイトルに「NIKKE」が含まれていても誤らない）
- **管理者権限で実行していない** … カーソルが動かない場合はこれです
- **押すのが早すぎる** … `runner/wait_for_image.py` の `CLICK_SETTLE` を増やしてみてください

## 画像が見つからない時

ゲームのアップデートでUIが変わると、参照画像が古くなって一致しなくなります。
実行ログには毎回の一致率が出るので、そこで判断できます。

```
画像、迎撃戦が見つかりません。一致率0.441/必要0.7。... 1/10回目の再確認。
```

- **0.9前後で止まる** … 閾値（`pass_confidence`）を少し下げれば通る
- **0.4程度** … 画像が古い。下記の手順で差し替える
- **画面遷移の直後に低い値が数回出る** … 正常（前の画面を見ているだけ）

### 一致率を調べる

リポジトリのルートフォルダで実行します。全画像の一致率と、赤枠を描いた画像が `debug_out/` に出力されます。

```bash
python -m runner.debug_match                 # 全部まとめて
python -m runner.debug_match interception    # 個別に
```

### 参照画像を差し替える

対象が写っている状態で、画面から切り出して保存します。

```python
from runner.debug_match import crop_from_screen
crop_from_screen(左, 上, 幅, 高さ, "interception.png")
```

## 画面表示（赤枠・自動操作中の案内）

- **赤枠** … 画像が見つかると対象の少し外側に枠を出し、マウス移動からクリックが終わるまで表示します。
  白い縁取り付きの赤線（二重線）なので、赤いボタンの上でも見えます。`runner/highlight.py` の定数で調整、`ENABLED = False` で無効化
- **自動操作中の案内** … 実行中は画面全体が薄暗くなり、中央に「自動操作中」と出ます。
  終了・中断・エラーのどの場合でも自動で消えます。`runner/overlay.py` の `ENABLED = False` で無効化。
  見た目だけ確認したい時は `python -m runner.overlay --show-in-capture`

どちらも次の3つを満たすように作ってあります。

| 性質 | 理由 |
|---|---|
| フォーカスを奪わない | 奪うとゲームが非アクティブになり、クリックが効かなくなる |
| クリックが素通りする | 表示の上からクリックしてもゲームに届くようにする |
| スクリーンショットに写らない | 写ると画像認識の一致率が下がる。`WDA_EXCLUDEFROMCAPTURE` で除外 |
